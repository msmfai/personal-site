Side Projects

Experiments in agentic coding and evidence-driven software development.

Side projects are where I experiment with agentic coding as a methodology, not a novelty. The interesting question is not whether an agent can produce code. It is how to structure the work so that long-running, cross-domain development remains falsifiable, inspectable, and under human direction.

Mario’s Mask

Play Majora’s Mask as Mario, with movement, attacks, swimming, voice, and animations adapted from Super Mario 64.

Source and methodology · Download the alpha

Mario’s Mask is an N64 project that ports Mario’s behaviour into a different game and engine. I used coding agents as persistent systems-engineering collaborators, but designed the process around a harder question:

Can agents carry behaviour across two independently decompiled games without losing its identity—and can that claim be tested rather than asserted?

Methodology

Use the source game as an oracle. The real Super Mario 64 ROM runs headlessly beside the mod. Both games stream Mario’s internal state into a comparator, with traces aligned on action edges rather than brittle wall-clock timing. A generated test arena is compiled into both games. The resulting suite cross-verifies 54 distinct actions across 22 scenarios, bit for bit, while testing the shipped speed adjustment as an explicit transform rather than hiding it as a tolerance.

Make goals the unit of agent work. Open problems were split into individual goal files with their own evidence and stopping conditions. State was updated at goal boundaries so work could survive across agent sessions. Tests for behaviour, performance, and regressions were agent-verifiable; play feel, voice calibration, and real-N64 behaviour were marked as human-only gates.

Instrument before inferring. Difficult runtime bugs were approached by making the system observable. Debug builds emit a structured event stream that can be drained, stored, and queried without changing release builds. Fault-injection switches test the diagnostics themselves. This turned an intermittent audio cutout and apparent emulator speed-up into a byte-level account of an invalid audio sequence span, followed by a permanent build invariant.

Layer evidence by what it can prove. Compile-time ABI assertions, post-link ROM audits, headless behavioural tests, multi-scene smoke tests, visual checks, accurate emulation, and physical hardware all answer different questions. The methodology records the uncertainty left by each layer instead of treating any single green check as universal proof.

Turn the release boundary into code. The public repository has clean history and automated checks that reject ROMs, extracted game assets, private paths, and unreviewed build products. The published artifact is a small cross-platform builder that combines two user-supplied games locally and verifies exact inputs and output.

What I learned

The useful leap was not making the agents more confident; it was making the world they worked in more legible. Goals exposed scope, oracles exposed behavioural drift, telemetry exposed causality, and human-only gates exposed where judgement still mattered. Mario’s Mask became both a game and an experiment in how to make agentic software development accountable to evidence.
